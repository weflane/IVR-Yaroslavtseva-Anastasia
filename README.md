# BookMatch

BookMatch — веб-приложение для подбора книг по текущему эмоциональному состоянию читателя. Пользователь проходит
короткий адаптивный тест и получает персональную подборку из 3–5 книг; кроме того, доступны рекомендации по
прочитанному, каталог с фильтрацией по тегам, личный кабинет, личные заметки и экспорт результатов.

## Возможности

**Для читателя**

* **Регистрация и вход.** Учётная запись создаётся по адресу электронной почты и паролю (не короче 6 символов).
  Аутентификация выполняется с помощью JWT-токенов, личные страницы защищены.
* **Адаптивный тест.** Четыре шага: настроение, жанр, темп чтения и длина книги. На каждом шаге предлагаются только
  те варианты ответов, для которых в базе остались непрочитанные книги, поэтому тест не приводит в тупик.
  Предусмотрены возврат на предыдущий шаг и повторное прохождение.
* **Персональная подборка.** По итогам теста формируется подборка из 3–5 книг с обложками, аннотациями и
  атмосферными тегами. Уже прочитанные книги в подборку не попадают.
* **Рекомендации по прочитанному.** Раздел «Рекомендации» подбирает книги по тегам прочитанных произведений.
* **Каталог.** Просмотр всех книг без прохождения теста, поиск по названию и автору, фильтрация по одному или
  нескольким тегам, постраничная загрузка.
* **Карточка книги.** Обложка, автор, описание, теги, объём и темп, а также «эмоциональная карта» — шесть шкал
  (грусть, радость, задумчивость, напряжение, темп, объём).
* **Поиск похожих книг.** Кнопка «Найти похожую книгу» предлагает до пяти книг с близким набором тегов.
* **Личный кабинет.** Списки «Прочитанное» и «Хочу прочитать», а также «История настроений» — дневник пройденных
  тестов с датами и полученными подборками.
* **Личные заметки.** К каждой книге можно добавить заметку (до 500 символов), изменить или удалить её. Заметки
  доступны только автору.
* **Экспорт.** Подборка, библиотека и карточка книги сохраняются в текстовый файл (.txt); подборка и карточка книги —
  также в виде изображения (.png).
* **Справка.** Раздел «Помощь» с пошаговым описанием всех действий и ответами на частые вопросы.

**Для администратора**

* Добавление, изменение и удаление книг через API (доступно только пользователям с правами администратора).
* Загрузка книг из файла JSON и генерация демонстрационных записей для проверки производительности.

**Эксплуатация**

* Запуск всего приложения в контейнерах Docker.
* Автоматическое резервное копирование базы данных по расписанию и скрипт восстановления.
* Модульные тесты, проверка стиля кода и автоматическая сборка в GitHub Actions.
* Скрипт нагрузочной проверки: одновременная работа 100 пользователей, замер времени подбора книг (требование — не
  более 3 секунд).

## Быстрый запуск

Требуется установленный Docker с поддержкой Docker Compose.
1. Создайте файл настроек из шаблона.
   Linux и macOS:
   ```bash
   cp .env.example .env
   ```
   Windows (PowerShell):
   ```powershell
   copy .env.example .env
   ```
2. Соберите и запустите приложение:
   ```bash
   docker compose up -d --build
   ```
3. Загрузите книги в базу данных:
   ```bash
   docker compose exec backend python seed_books.py
   ```

После запуска доступны:
* приложение - <http://localhost:8080>;
* интерактивная документация API - <http://localhost:8000/docs>.

## Настройка

Параметры задаются в файле `.env` (шаблон — `.env.example`). Файл `.env` содержит секреты и не публикуется в
репозитории.

* `MONGODB_URL` - Адрес подключения к MongoDB. В Docker имя узла — `mongo`; логин и пароль должны совпадать с `MONGO_USER` и `MONGO_PASSWORD` 
* `MONGODB_DB_NAME` - Имя базы данных (по умолчанию `bookmatch`) 
* `SECRET_KEY` - Секретный ключ для подписи токенов; рекомендуется случайная строка не короче 32 символов
* `ALLOWED_ORIGINS` - Список адресов сайта, которым разрешены обращения к API (через запятую)
* `MONGO_USER`, `MONGO_PASSWORD` - Учётные данные администратора базы данных в контейнере  
* `BACKUP_INTERVAL_HOURS`, `BACKUP_KEEP_DAYS` - Периодичность резервного копирования (24 часа) и срок хранения копий (14 дней)
* `VITE_API_URL` - Адрес API при локальной разработке фронтенда; в Docker задаётся автоматически
Перед использованием вне учебной среды необходимо заменить пароль базы данных и `SECRET_KEY`.

## Локальная разработка

Необходимы Python 3.12, Node.js 20 или новее и запущенная MongoDB.
```bash
docker compose up -d mongo
cd backend
pip install -r requirements.txt
python seed_books.py
uvicorn main:app --reload
cd frontend
npm install
npm run dev
```

## Каталог книг
Скрипт `backend/seed_books.py` заполняет базу. Он только добавляет и обновляет записи и ничего не удаляет, поэтому
его можно запускать повторно.
* `python seed_books.py` - Добавить или обновить базовый набор книг и теги
* `python seed_books.py --demo 1000` - Довести общее число книг до 1000 демонстрационными записями (автор «Демо-автор») для проверки нагрузки
* `python seed_books.py --clear-demo` - Удалить демонстрационные книги
* `python seed_books.py --json books.json` - Импортировать собственные книги из файла JSON
В Docker команды выполняются в виде `docker compose exec backend python seed_books.py ...`.

## Администрирование

Добавлять, изменять и удалять книги через API (`POST`, `PUT`, `DELETE /books`) может только администратор.
Чтобы назначить администратора, сначала зарегистрируйте пользователя на сайте, затем выполните:
```bash
docker compose exec backend python make_admin.py почта@пример.рф
```

## Резервное копирование

Служба `backup` каждые 24 часа создаёт копию базы данных (`mongodump`) в каталоге `backups/` и хранит её 14 дней.
```bash
./scripts/backup.sh
./scripts/restore.sh backups/bookmatch-ГГГГММДД-ЧЧММСС.archive.gz
```

## Тестирование и контроль качества

```bash
cd backend && python -m pytest tests
cd frontend && npm run lint
flake8 backend
python scripts/load_test.py --users 100 --report loadtest_report.md
python backend/cleanup_loadtest.py
```

В GitHub Actions настроены два сценария:
- **«Тесты и проверка кода»** (`tests.yml`) запускается при каждой отправке изменений и запросе на слияние:
  проверка стиля Python, модульные тесты, проверка стиля интерфейса (ESLint) и сборка сайта.
- **«Контейнеры и развёртывание»** (`docker.yml`) собирает образы сервера и сайта, публикует их в реестре GitHub
  и запускает развёртывание на сервере, если в настройках репозитория задан секрет `DEPLOY_HOOK_URL`.

## Структура репозитория

```text
backend/            сервер на FastAPI: маршруты (app/routers), модели, логика подбора, генерация PNG, тесты

scripts/            резервное копирование и восстановление базы, нагрузочная проверка
docs/               дополнительная документация
backups/            каталог для резервных копий базы данных
.github/workflows/  сценарии GitHub Actions
docker-compose.yml  описание сервисов: сайт, сервер, база данных, резервное копирование
.env.example        шаблон файла настроек
```
